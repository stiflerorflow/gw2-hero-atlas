# Account workspace and guided onboarding

17 October 2026. This extends the buildless GitHub Pages guide with an eight-view navigation including default `#home` (Start here). No backend, analytics, runtime package dependency, account login or automated game action was added.

## Official contracts and live checks

- [Character training](https://wiki.guildwars2.com/wiki/API:2/characters/:id/training): account + characters + builds. Response historically `{training:[{id,spent,done}]}`; the Wiki documents an ongoing empty-data bug. Arrays and wrapped records are accepted; empty/failed results mean unknown, never untrained. Track IDs are mapped to elite specs using the public [professions](https://wiki.guildwars2.com/wiki/API:2/professions) training catalogue fetched during this work. Personal full-training confirmations are separate, profession-validated and labelled; stored templates are not training evidence.
- [Account](https://wiki.guildwars2.com/wiki/API:2/account): only reported positive expansion access can be explicitly applied to the gear planner. Path of Fire implies HoT. No weapon unlock, map reveal, hero point ledger or character-specific jade core is granted.
- [Bank](https://wiki.guildwars2.com/wiki/API:2/account/bank), [shared inventory](https://wiki.guildwars2.com/wiki/API:2/account/inventory), [material storage](https://wiki.guildwars2.com/wiki/API:2/account/materials) and [character bags](https://wiki.guildwars2.com/wiki/API:2/characters/:id/inventory): inventories scope in addition to the base account/character scopes. Null slots handled; all listed characters scanned, with bounded concurrency. Metadata resolves selected stat ID ahead of fixed item defaults. Counts do not include equipped gear on unimported templates, guild banks, Trading Post orders or unopened containers. Material storage is counted once and is separately searchable by name.
- [Achievement progress](https://wiki.guildwars2.com/wiki/API:2/account/achievements) and [masteries](https://wiki.guildwars2.com/wiki/API:2/account/masteries): progression scope. Only the guide’s73 mastery-achievement records are retained from achievements. `done===true` verifies completion; missing/partial records do not. Mastery `level` is zero-indexed; relevant positive travel-masteries use the public catalogue fetched during this work and follow revealed route requirements. These records are not an unspent mastery balance.
- [Wallet](https://wiki.guildwars2.com/wiki/API:2/account/wallet): wallet scope; integer amounts and stable currency IDs, with coin formatted in gold/silver/copper. Public currency metadata fetched to verify IDs1Coin,3Laurel,23SpiritShard,24PristineFractalRelic,63AstralAcclaim.
- [Laurel Merchant](https://wiki.guildwars2.com/wiki/Laurel_Merchant) and [ascended trinket acquisition](https://wiki.guildwars2.com/wiki/Ascended_trinket): verified costs30Laurels/amulet,35/ring,40+50ecto/accessory for supported stat families. Each is a separate alternative using the same balance, not a cumulative affordable shopping list. Exact variants, unique-item restrictions, vendor access and current balances require in-game verification. No claim that every prefix is available, or that this is the cheapest route.
- Browser authentication: official [API-key documentation](https://wiki.guildwars2.com/wiki/API_key) explains that authorization-header preflight is unsupported. A real OPTIONS probe failed404; a real browser GET with a deliberately invalid key in the official HTTPS `access_token` parameter returned a readable401. The importer now uses this browser-compatible format. No real account key was available; successful authenticated imports use fixtures for validation.

## Behaviour and privacy

Guided setup covers ArenaNet sign-in/new key, six permission choices, connecting and troubleshooting, then account scan, independent equipment/build tabs and partner sharing. Base permissions account/characters/builds remain required; inventories/progression/wallet are optional. Optional failures preserve previous data and its date, with failed/missing status. Disconnect/pagehide aborts work and clears the key; stale responses cannot commit. Refresh commits the account snapshot after the scan, not after each partial response.

Four account records, twelve equipment snapshots,100listed characters,5000stored inventory stacks and3000material-storage entries are bounded. Inventory scans prioritise equipment/upgrade records if storage is capped and explicitly flag incomplete coverage. LocalStorage failure preserves the previous raw save and offers exports; the application does not claim durable persistence when it failed.

Keys are neither saved nor shared. Authenticated request URLs do carry the key to the official API, as documented in the UI; no key enters page navigation, history, account exports or full backups. Snapshots contain personal account IDs, character names, equipment/resources and progress. Item-name browsing requires an explicit checkbox and resets across accounts. Shared files are data snapshots supplied by the user, not proof of a live server connection.

The planner checks level/tier, primary stat family, armour weight, physical item quantity and recorded binding eligibility. Spare items from another account cannot match. Target blueprints remain separate from actual equipped weapons/roles. Empty rune/sigil/relic records are review prompts; exact upgrade suitability, legendary copies, crafting recipes/costs and combat boon uptime remain source/in-game checks. Duo advice uses confirmed specs and gives specific player next steps, not guaranteed performance.

The optional API mastery view is read-only and tied to the selected account; manual mastery ticks are preserved in a separate ledger. API imports do not mutate hero-point progress, personal journal, map reveals or duo availability. Account-only partner files merge one account without replacing other guide progress; malformed/conflicting/oversized files fail before mutation.
