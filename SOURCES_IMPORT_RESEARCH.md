# Sources and optional account imports

Reviewed 17 October 2026. The Sources & evidence tab separates selected builds from alternative variants, editorial ratings and published benchmarks. Added provider coverage: official GW2 API, GW2 Wiki, Snow Crows, MetaBattle, Accessibility Wars, Masel, Lord Hizen, GuildJen, Discretize optimizer and GW2 Wingman. Old Discretize guides are archival; optimizer is a separate current tool. Historical Hizen demonstrations and revision-unconfirmed alternatives are labelled accordingly. External pages can reveal spoilers.

Official endpoint contracts: https://wiki.guildwars2.com/wiki/API:2/characters/:id/equipmenttabs and https://wiki.guildwars2.com/wiki/API:2/characters/:id/buildtabs plus `/tokeninfo`, `/account`, `/characters`, character `/core`, `/items`, `/itemstats`, `/skills`, `/traits`, `/specializations`. Public item/stat metadata was fetched during research. Private account behaviour is verified using mocked API responses; no real personal API key was available during development.

The optional browser import requires account, characters and builds permissions. It imports independently selected equipment/build templates, resolves chosen stats ahead of item defaults, records binding, upgrades and item level/tier, and saves up to twelve offline snapshots. The optional account workspace now also reads bank, shared slots, bags/material storage, progress and wallet when permitted. It never infers a trained spec from a stored build template. Snapshot comparisons remain conditional on upgrades, actual bindings and available legendary copies.

Keys exist in memory only. Browser authentication uses the official API’s `access_token` URL parameter over HTTPS, only to `api.guildwars2.com`, with omitted credentials, no-store caching and no referrer. The previously implemented Authorization-header approach was incompatible with GW2’s unsupported browser preflight and has been replaced. A real-browser invalid-key request now returns a readable401 rather than a CORS failure. Request URLs can be visible to local developer tools and the API service; keys never appear in the page URL/history or stored/shared data. Disconnect/pagehide clears the key and pending work. Keys are excluded from local saves, backups and copy output. Snapshots contain personal character/account identifiers and equipment; progress backups therefore contain that personal data. Users should share backups deliberately. There is no backend, analytics or automatic two-person sync.

Matt and Steve can maintain separate account imports and share an account-only file from Start here. Import confirms replacement of that account only and leaves other accounts and manual guide progress intact. Whole-guide progress backups still replace guide state after confirmation. Neither flow provides automatic multi-user sync.
